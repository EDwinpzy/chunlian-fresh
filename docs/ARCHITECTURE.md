# 架构决策记录（ADR）｜春连鲜选

本文记录目标代码中的端形态与核心业务约束。生产仍运行旧业务版本，新业务部署尚未开始；部署事实和测试边界见 HANDOVER.md、docs/DEPLOYMENT.md 与 docs/TESTING.md。

## ADR-001 顾客端：网页版与原生 Android 双端

- 状态：已采用。
- 决策：顾客网页由 Vue 3 + Vite 实现；顾客 Android 使用 Kotlin + Jetpack Compose 独立原生实现。两端共用后端 API 和产品规则。
- 理由：满足网页与 Android 使用场景，同时保留原生设备交互与界面，不把网页包进 WebView 作为 Android 客户端。
- 目录：apps/customer-web/、apps/customer-android/。

## ADR-002 商家端：原生 Android 管理系统

- 状态：已采用。
- 决策：店主日常经营功能由 Kotlin + Jetpack Compose 原生 App 提供，包括商品、库存、订单、收款核实、退款核实和经营数据。
- 目录：apps/merchant-android/。ShopXO Web 管理后台仍用于基础维护和排障。
- 约束：生产分发需使用项目方控制的 release 签名材料；签名材料位于 Git 忽略目录，文档不得包含密码或私钥。

## ADR-003 订单状态拆成四个维度

- 决策：履约、支付、顾客收货确认和订单修订分别维护状态，不用一个布尔字段代替。
- 后果：COD 已送达未收款可处于“已送达 + 未付款”；统计保留应收，不自动记为实收。
- 实现位置：backend/extension/src/Domain/ 与 OrderStateMachine.php。

## ADR-004 订单修订采用版本、幂等与差价核算

- 决策：订单修订携带客户版本并使用幂等键；金额差额以整数分计算。补款完成前不得开始配送；失败不得覆盖生效中的旧订单版本。
- 已付款 OFFLINE_QR 订单减量时，新明细和总额立即更新，修订处于 APPLYING，退款流水保持 PROCESSING；APPLYING 期间禁止配送和再次改单。店主核实实际退款后，退款记录才成功、修订转为 COMMITTED。
- 并发冲突由服务端版本校验处理。API 细节见 docs/API.md。

## ADR-005 线下扫码支付和人工退款核实

- 决策：顾客支付方式为 OFFLINE_QR 或 COD。店主在商家 App 上传收款二维码。顾客扫码并不自动改变订单付款状态，商家核实到账后才记录收款。
- 补款：对预付订单改单产生应补金额时，商家核实实际到账后记录补款，之后按当前修订流程提交新版本。
- 减量退款：提交修订后新明细和总额立即生效，修订保持 APPLYING、退款流水保持 PROCESSING，并阻止配送和再次改单；店主核实款项确已退回后，才将退款记为成功并把修订转为 COMMITTED。
- 取消退款：店主确认款项确已退回后，才能记录成功退款。系统不调用微信退款 API，也不依赖第三方支付回调。
- 约束：幂等、订单版本、实际资金核对与审计记录仍然必需。

## ADR-006 COD 收款并入确认送达

- 决策：COD 确认送达时由店主选择“已收款并送达”或“仅送达未收款”；默认不得预选已收款。未收款仍进入应收。
- 补记收款作为单独操作并记录审计。

## ADR-007 金额统一使用整数分

- 决策：API 和领域计算使用整数分；数据库金额字段使用兼容的精确数值类型。不得用浮点数累计人民币金额。
- 展示层负责将分格式化为元。

## ADR-008 单机模块化后端

- 决策：现有 ShopXO 部署承载 PHP 扩展与数据库，采用模块化单体；保持单店、低并发下的简单部署方式。
- 运维约束：最近核验磁盘使用率约 95%，可用空间约 1.7 GB，服务器与其他服务共享。该数据会变化，任何部署、上传、日志或备份操作前都必须重新核验容量。
- 网络：生产 HTTPS 已在 https://103.236.97.137:8096 启用并验证，NAT 映射已创建。TLS 使用项目私有 CA；Android 按精确 IP 信任，网页用户须手动安装或信任 CA。

## ADR-009 统一经营日期

- 店铺经营日期和预约时间使用 `Asia/Shanghai`。PHP 插件请求采用该时区，插件 PDO 连接设置 `+08:00`；不改变共享主机或数据库全局时区。
- 顾客网页、顾客 Android 的预约与时间显示，以及商家 Android 的统计日期区间均使用店铺时区，不依赖设备时区。
- 商家统计切换区间时取消旧请求，并检查请求序号；较早请求的结果或错误不能覆盖最新选择。

## ADR-010 公开图片请求

- 商品图片与收款二维码可能是服务器根相对路径。Android 在加载前按配置的服务地址解析成可请求的 URL。
- 顾客图片加载使用独立网络客户端，不附加顾客 API 的 Bearer 凭据。图片失败时显示说明并允许重新加载。

## 一、结论先行

**8095 端口无法从公网访问，原因不是安全组配置错误，也不是 Nginx 配置问题，而是：**

> **该服务器是运营商 NAT 后的虚拟机，服务商只向本机转发了 `80` 与 `8888` 两个端口；其余端口在运营商边缘即被丢弃。**

而 **80 端口被服务商的备案（ICP）拦截页劫持**。

**我无法自行解决** —— 这需要服务商侧的操作。下面给出精确证据与三个可选方案。

---

## 二、证据链

### 2.1 外网可达性实测（从本机 + 第三方独立探针）

| 端口 | 外网可达 | 说明 |
|---|---|---|
| 22 | ✅ | SSH |
| **80** | ⚠️ 可达但被劫持 | 返回服务商备案拦截页 |
| 443 | ❌ | 边缘丢弃 |
| 8080 | ❌ | 边缘丢弃 |
| 8443 | ❌ | 边缘丢弃 |
| **8888** | ✅ | 正常响应（见 2.3） |
| 8095 | ❌ | 边缘丢弃 |
| 3000 / 5000 / 8000 / 8090 / 9000 | ❌ | 边缘丢弃 |

独立第三方探针（allorigins）访问 `103.236.97.137:8095` → **408 Request Timeout**，与本地结论一致。

### 2.2 80 端口返回的是备案拦截页

```
$ curl http://103.236.97.137/          # 从真实外网
HTTP/1.1 404
（GBK 编码内容，解码后：）

  温馨提示：该网站暂无法访问 (code:7l8yacEXs8esfm)
  原因一：根据《非经营性互联网信息服务备案管理办法》，
          您尚未进行备案或接入。
  原因二：您的网站可能含不良信息，请联系网站管理员。
  本页为默认提示页，如网站存在以上问题请及时处理。
```

> **注**：本机 `curl 127.0.0.1:80` 返回的是 nginx 默认欢迎页（200）——
> 因为**本机回环不经过服务商边缘**。这正说明拦截发生在本机之外。

### 2.3 8888 端口不属于本机

```
$ ss -tlnp | grep 8888
（无输出 —— 本机没有任何进程监听 8888）

$ curl http://127.0.0.1:8888/
000（本机不可达）

$ curl http://103.236.97.137:8888/health    # 从真实外网
{"code":200,"message":"success","data":{"service":"invoice","status":"UP"}}
```

**结论**：8888 由服务商边缘转发到**另一台机器**（某个 `invoice` 服务），完全不在本机。

### 2.4 本机真实网络身份

```
$ ip -4 addr
2: ens17: inet 172.16.2.71/12          ← 真实地址是私有 IP
$ ip route
default via 172.16.0.1 dev ens17

$ hostname
liuliangRrH8b6Cgmpi6                   ← "流量" 计费型实例
```

`103.236.97.137` 是服务商 NAT 映射，**不是本机拥有的地址**。

### 2.5 NAT 表仅为 Docker 自建

```
Chain DOCKER
DNAT  tcp dpt:8080 to:192.168.16.10:8080
DNAT  tcp dpt:8443 to:192.168.16.10:8443
```

这两条是 Docker 自动生成的容器端口映射，**不是**服务商端口转发规则。

## 四、解决方案（三选一，均需你在服务商侧操作）

### 方案 A：申请服务商转发 8095（**推荐**）

在磐石云控制台的「端口映射 / 端口转发」处，为 `103.236.97.137` 增加：

```
外网端口 8095  →  内网 172.16.2.71:8095
```

**代价**：无。**风险**：无。
**之后**：`http://103.236.97.137:8095/` 即可访问安装向导。

---

### 方案 B：改用 8080 或 8443（若这两个端口对外已放行）

你现有的自建栈占用了 8080/8443（Docker nginx）。当前外网访问这两个端口**超时**，
说明服务商未转发。

若服务商控制台显示这两个端口「已开启」，则可让我：
- 把 ShopXO 挂到宿主机 nginx 的 **8080**，并把原 Docker nginx 让到其他端口
- 或直接在 Docker nginx 里加一个 `server{}` 反代到 `172.16.2.71:8095`

**代价**：需改动现有服务，风险高于方案 A。

---

### 方案 C：做 ICP 备案，走 80/443

备案通过后，`80` 才会返回你的站点而非拦截页。

**代价**：备案需数个工作日，需域名与主体资质。
**这是长期正解**，但不是当下能立刻推进的。

---

### 方案 D：本机 SSH 隧道（**临时预览，立即可用，无需服务商配合**）

若你只是想**先看一眼安装向导**、把 ShopXO 装完，可在**你自己的电脑**上执行：

```bash
ssh -p 55560 -L 8095:127.0.0.1:8095 root@103.236.97.137
```

保持该终端不关闭，然后浏览器打开：

```
http://127.0.0.1:8095/
```

即可看到 ShopXO 安装向导。

**优点**：立刻可用，零配置变更。
**缺点**：仅你自己可见；每次需开隧道；不适合面向真实用户。

> ⚠️ 注意：安装向导中填写的「站点域名」应填最终对外地址
> （如 `http://你的域名/`）。若先用隧道安装，建议先填
> `http://103.236.97.137:8095/`，待方案 A/C 落定后再修正。

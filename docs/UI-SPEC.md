# UI 规范｜春连鲜选 双端设计系统

> 来源：方案 §4–§7A。本文档是编码实施的**权威 token 与尺寸来源**。

## 1. 视觉总纲

**目标气质**：安静、精致、可信、亲切的精品生鲜零售。避免传统商家后台的密集表格、粗线条彩色按钮与杂乱入口。

**两端共用品牌语言，信息权重不同**：顾客端突出商品图片与购买；商家端突出订单优先级、操作效率和收款准确性。

### 1.1 品牌关键词 / 禁用视觉

**关键词**：自然留白、森林绿、奶油白、柔和香槟金、真实生鲜摄影、圆润但不幼稚、可信的状态反馈。

**禁用**：满屏渐变、过饱和荧光绿、大面积彩虹按钮、频繁弹窗、浮夸 3D 图标、把金额藏起来、传统 ERP 式密集表格、深阴影堆叠、超多顶部导航。

## 3. 字体、字号、排版

- 字体首选系统中文无衬线：`PingFang SC`（iOS/微信）、`Noto Sans CJK SC` / Android 系统字体；**不打包商业字体文件**。
- 数字显示开启 tabular figures（`font-variant-numeric: tabular-nums` 或等宽数字回退），金额对齐。
- **小程序以 750rpx 设计稿宽度**。下表 `px` 为 375pt/375 CSS px 设备基准的**设计像素**，换算到 750rpx 稿约乘 2；安卓端以 `dp/sp` 为单位，不强行用 rpx 管原生安全区域。

| 文字角色 | 375pt 基准 | 750rpx 对应 | 字重 | 行高 |
|---|---:|---:|---|---:|
| 大数字/营业额 | 28px | 56rpx | 700 | 1.15 |
| 页面标题 | 24px | 48rpx | 650/700 | 1.28 |
| 区块标题 | 18px | 36rpx | 600 | 1.35 |
| 商品名称 | 15px | 30rpx | 600 | 1.45 |
| 普通正文 | 14px | 28rpx | 400/500 | 1.55 |
| 辅助文字 | 12px | 24rpx | 400 | 1.45 |
| 最小补充文字 | 11px | 22rpx | 400 | 1.4 |
| 价格 | 20px | 40rpx | 700 | 1.2 |

**强制要求**：关键商品信息和操作说明尽量不低于 12px；大字体/系统缩放测试不截断价格、订单总额或按钮。

## 4. 布局、间距、阴影、圆角

- 页面左右安全边距：小程序 **16px / 32rpx**；安卓 **16dp**。
- 8pt spacing：`4/8/12/16/20/24/32` → `8/16/24/32/40/48/64rpx`。
- 卡片间距 12–16px；卡片内距 14–16px；区块上下距 24px。
- 商品图优先 1:1 高清；首页双列网格卡片间隔 12px。
- 圆角：按钮 14px；小卡片 16px；大卡片 20px；浮层 24px；胶囊 999px。
- 阴影：仅弹窗和悬浮操作区使用轻阴影，如 `0 6px 24px rgba(18,45,31,.07)`；默认卡片主要靠浅边框分层。
- 分隔线 1px `#E7EAE4`，不使用黑色粗边框。
- 主按钮高度 48–52px；次级按钮 44–48px；任何点击目标 ≥ 44×44pt（安卓近似 48dp）。
- Android 状态栏/刘海/底部手势区与微信小程序胶囊按钮周边使用**平台运行时安全区**，不得硬编码固定状态栏高度。

## 5. 图标、图片、动态反馈

- 图标统一 24px（主要入口）/ 20px（辅助），2px 线性描边，端点圆角；只用已授权资源。
- 生鲜图片：真实摄影、浅背景、柔和侧光，不用 AI 图冒充实物；压缩为 WebP/AVIF 并回退 JPEG。
- 骨架屏：商品网格、订单列表、工作台分别独立实现，避免空白闪烁。
- 交互动画 150–220ms、`ease-out`，避免复杂动效干扰接单。
- 正确状态四件套：图标 + 简短文字 + 下一步建议 + 可恢复操作（如"支付确认中，请稍后刷新"）。
- 空态：单色小图标、说明、主按钮；错误态不能依赖纯颜色。

## 6. 响应式规则

| 场景 | 规则 |
|---|---|
| 顾客小程序 | 320–430pt 常见手机宽；双列卡片不足空间时文字省略而非价格溢出；尽量保持两列，极窄屏经验证可切一列 |
| 安卓 App | 360–480dp 手机；统计两列卡片，小屏确保完整金额；横屏以单列订单详情优先 |
| 大字号 | 顾客商品名称最多两行，金额和按钮不能因文字放大重叠 |
| 长地址 | 订单详情允许 2–3 行，地址可复制，不用单行省略导致配送错误 |
| 安全区 | 底部固定按钮内缩 `safe-area-inset-bottom`，系统返回优先处理未保存表单确认 |

## 7. 顾客小程序（微信）页面规格

### 7.1 信息架构与导航

- 底部导航 **4 项**：`首页 / 分类 / 购物车 / 我的`，选中绿色、未选中灰色；购物车有数量角标。
- 订单从"我的"进入，不单独占 Tab；搜索从首页/分类进入。
- 顶层路线：`首页 → 商品详情 → 购物车 → 确认订单 → 支付/下单结果 → 订单详情 → 修改/取消/收货`。
- 返回原则：提交付款后不再返回可二次提交的旧结算页；通过订单详情处理后续事务。

### 7.3 UI-C02｜商品详情

```text
┌─────────────────────────────────┐
│ ‹ 商品详情                  分享 │
│ ┌─────────────────────────────┐ │
│ │      大幅商品摄影 1:1        │ │  可左右切换商品图
│ └─────────────────────────────┘ │
│ ¥3.50       新鲜小青菜          │
│ 约500g/份     库存充足           │
│ 规格： [500g/份 ✓] [1kg/份]     │
│ 数量：                     - 1 +│
│ --------------------------------│
│ 商品说明 · 产地 / 保存提示        │
│ [购物车 3]    [加入购物车]       │  底部固定主操作
└─────────────────────────────────┘
```

- 商品照片顶部 1:1，圆角仅下边缘 24px；下滑后由紧凑顶部栏保持标题。
- 当前售价 24px 深砖红；商品名称 20px 深墨，规格灰字 13px。
- SKU 选择为胶囊按钮，选中绿色描边 + 浅绿底；无货不可选、提示"已售罄"。
- 数量加减 200ms 反馈，服务端最终库存校验。
- 底部左侧购物车入口（带角标），右侧深绿主按钮"加入购物车"；成功用非阻塞 toast，不强制跳转。
- 错误/空态：商品已下架、无库存、网络失败，各有返回首页入口。

**购物车（独立页）**

**确认订单**

```text
┌─────────────────────────────────┐
│ ‹ 确认订单                       │
│ ┌─────────────────────────────┐ │
│ │ 张先生   138****8888        │ │
│ │ 阳光小区3栋502室         ›  │ │
│ └─────────────────────────────┘ │
│ 期望送达时间                     │
│ (●) 尽快配送                    │
│ ( ) 预约送达    [选择日期及时间] │
│ ┌─────────────────────────────┐ │
│ │ 商品小计            ¥35.80  │ │
│ │ 配送费               ¥0.00  │ │
│ └─────────────────────────────┘ │
│ 支付方式                         │
│ (●) 货到付款                    │
│ ( ) 微信支付                    │
│ 订单备注（选填）                  │
│     合计 ¥35.80       提交订单   │
└─────────────────────────────────┘
```

- 结算页内容从上至下：**地址 → 期望配送时间 → 商品及金额 → 支付方式 → 备注 → 固定结算按钮**；切忌让配送时间藏在三级菜单。
- `尽快配送` 是业务文案，不展示"30 分钟送达"承诺。`预约送达` 通过平台日期时间选择器选到分钟；时区取服务器经营时区，后台校验晚于当前。
- 支付方式两张大选择卡（≥44px 点击高度），默认**上次成功使用的方式**；首次展示两种让用户选择，不替顾客未经确认选中 COD。
- `货到付款` 按钮文案"提交订单"；`微信支付` 按钮文案"微信支付 ¥XX.XX"。
- 配送费总额变化时立即刷新；未登录引导微信登录，但不清空购物车。
- 下单按钮有提交中禁用态（防重复提交），失败保留用户填写内容；下单成功不允许复用提交 token。

**订单详情页面关键区别**：

- 「待付款」「待配送」展示「修改订单」「取消订单」，状态和最新版本由服务器决定；
- 「配送中」「已送达」「已完成」隐藏修改/取消，提供售后/联系；
- 已取消且退款中的订单显示两个并行信息：**履约已取消 + 款项退款处理中**。

## 8. 商家 Android App 页面规格

### 8.1 信息架构

- 底部仅 **4 个 Tab：`工作台 / 订单 / 商品 / 我的`**。
- 营业统计放在工作台数字卡和"全部统计"二级页面；不为低频统计占用底部空间。
- 商品管理不跳 Web 后台；改价、上架、库存与拍照均在 App 内完成。
- 只提供店主一个管理员账号，支持以后增加只读账号，首期不做组织权限体系。

### 8.2 UI-A01｜工作台

- 改价、退款、COD 收款属敏感动作，须二次确认 + 审计记录；网络超时先查询状态再决定是否重试。

### 8.7 安卓细节交互标准

- 工作台打开时 10–20 秒轮询待处理数据可作为首期兜底，**不是后台保活保证**；生产需在真实安卓机验证通知权限、推送通道和 OEM 省电策略。
- 新订单提醒点击后从后端请求最新版本，绝不把通知文案当订单权威数据。
- 商家订单卡"顾客已修改"提醒持续至店主打开并查看最新版本后才标已阅；不能只读缓存。
- 点击「开始配送」前若服务器检测到待补款，提示"顾客有待支付的订单变更，暂不能配送"。
- Android 返回键：表单修改未保存时出现「舍弃修改 / 继续编辑」；从订单详情返回列表恢复原筛选和滚动位置。
- 订单状态变化后用非阻塞提示及卡片动画，避免不必要的确认层级；但**真实收款必须二次确认**。

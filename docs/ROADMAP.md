## 4. 真实开发顺序建议

1. **第一关**：先做 ShopXO 源码审计、COD/预约时间/在线退款闭环的可行性验证，锁 commit。
2. **第二关**：把领域层（四维状态、差价、资金、幂等）与扩展表做扎实，先让单测全绿。
3. **第三关**：商家端 API 走通一笔 COD 与一笔在线付款订单的完整流转。
4. **第四关**：加入最关键的「配送前改单 + 增减商品的补退款」，集中处理并发、库存与支付异常。
5. **第五关**：生产安全/合规、数据库备份与恢复演练，完成验收交接。

## 5. 源码审计必须先做的事

1. 锁定 ShopXO 后端的**可运行提交哈希**，记录 PHP/MySQL/依赖版本。
2. 查看 ShopXO 6.9.2 实际订单表、状态字段、订单商品快照、库存预占、库存回退和付款流水实现。
3. 验证微信支付/退款是否已按官方 APIv3 要求使用正确签名、回调、查单，避免重复实现。
4. 在后台开启「下单指定时间」后，检验其字段与 API，并确认能否表达"尽快配送"。
5. 验证线下支付插件和「线下支付正常进行」开关是否能令 COD 订单正常待配送。
6. 盘点订单取消、退款服务：哪些动作可复用、哪些不能绕过官方业务钩子。
7. 审核顾客 `order/detail`、`order/index` 和 `order/collect` 当前版本的鉴权与参数，**不照抄 2021 年文档**。
8. 确认后端插件开发规范、服务扩展方式和数据库表前缀，避免直接改 `vendor`、核心支付 SDK。
9. 审核已有会员、地址、登录、隐私处理能力，避免另造重复表。
10. 审核后端权限中"管理员只能访问商家 API"的粒度和登录限速。
11. 核对许可证与收费插件边界：**MIT 核心许可不自动覆盖所有插件、图片和商用第三方素材**。

### 6.3 关键技术选型（已锁定，实现与之一致）

| 项 | 选型 |
|---|---|
| 后端宿主 | ShopXO 6.9.2（ThinkPHP 8） |
| 领域层 | 零框架依赖的纯 PHP（`Chunlian\` 命名空间，手写 PSR-4 自举） |
| 数据库 | MySQL 8；扩展表前缀 `veg_`，无外键 |
| 后台任务 | cron + 数据库 outbox（**不当秒级消息通道**） |
| 金额 | 一律整数「分」（`*_fen`） |
| 并发 | 行锁 + 乐观锁 `WHERE version = ?` |
| 部署 | apt 原生 LAMP（**不用 Docker** —— 服务器出网受限） |

# 开发路线与交付边界｜春连鲜选

> 来源：方案 §14、§17、§20.2，以及**本次代码实现的真实完成度声明**。

## 1. 分阶段开发计划

> 工作量是**规划估算**，不是已完成源码审计后的报价。建议至少具备 PHP/ThinkPHP（后端）、uni-app（微信小程序）、Kotlin/Compose（原生安卓）三类技能。

| 阶段 | 工作项 | 人天估算 | 输出 / 验收门槛 |
|---|---|---:|---|
| 0. 可行性审计 | ShopXO 6.9.2、uni-app 依赖、COD/时间/退款可复用性 | 4–7 | 源码差距表、固定版本、风险确认 |
| 1. UI 定稿 | 跨端设计系统、六屏高保真、全部页面/状态、交互流程 | 10–16 | 六屏高保真 + 全页面组件变体评审通过 |
| 2. 基础商城 | 后端部署、商品、库存、登录、购物车/订单 | 8–12 | 小程序下单闭环 |
| 3. **原生安卓 App** | Android Studio + Kotlin/Compose、登录、工作台、商品 CRUD、订单/通知、合并送达收款 | 22–36 | APK 真机完成 COD 订单全过程 |
| 4. 订单修订 | 配送前编辑/取消、补款、退款、库存并发、审计 | 18–30 | 资金与并发测试通过 |
| 5. 正式上线联调 | 微信支付/退款/备案/发货、真机适配、压测、回滚 | 10–18 | P0 全验收完成 |
| **合计** | 按独立人天累计（部分可并行） | **72–119 人天** | 以源码审计结果校正 |

- **2 名覆盖三类技能的工程师并行**：建议预留 **10–16 周**，设计验收、支付资质与微信审核可能额外等待。
- **1 名同时熟悉 PHP、uni-app、原生 Android 的开发者**：建议预留 **16–26 周**。
- 若先不做"已支付订单自由增减商品"，能更快上线，但**不符合当前已确认的 P0 需求**，不得把阉割版当作完整第一版交付。

## 4. 真实开发顺序建议

1. **第一关**：先用一周做 ShopXO 源码审计、COD/预约时间/在线退款闭环的可行性验证，锁 commit。
2. **第二关**：在设计工具中完成**六个重点高保真页面 + 其余页面完整组件状态**，设计评审通过后再编码。
3. **第三关**：顾客端先走通一笔 COD 与一笔在线付款订单；Android Compose 跑通"订单打开 → 开始配送 → 合并确认送达/收款"。
4. **第四关**：加入最关键的"配送前编辑/取消订单 + 增减商品的补退款"，集中处理并发、库存和支付异常。
5. **第五关**：国内真实安卓手机通知测试、微信小程序真机体验、生产安全/合规验证，完成验收交接。

## 5. 源码审计必须先做的 12 件事

1. 锁定 ShopXO 后端与 `shopxo-uniapp` 的**可运行提交哈希**，记录 PHP/MySQL/依赖版本。
2. 查看 ShopXO 6.9.2 实际订单表、状态字段、订单商品快照、库存预占、库存回退和付款流水实现。
3. 验证微信支付/退款是否已按官方 APIv3 要求使用正确签名、回调、查单，避免重复实现。
4. 在后台开启「下单指定时间」后，检验其字段与 API，并确认能否表达"尽快配送"。
5. 验证线下支付插件和「线下支付正常进行」开关是否能令 COD 订单正常待配送。
6. 盘点订单取消、退款服务：哪些动作可复用、哪些不能绕过官方业务钩子。
7. 审核顾客 `order/detail`、`order/index` 和 `order/collect` 当前版本的鉴权与参数，**不照抄 2021 年文档**。
8. 审核 uni-app 微信小程序构建版本（Vue2/Vue3、组件依赖、分包、微信支付 UI 和 `request_url` 入口）。
9. 确认后端插件开发规范、服务扩展方式和数据库表前缀，避免直接改 `vendor`、核心支付 SDK。
10. 审核已有会员、地址、登录、隐私处理能力，避免另造重复表。
11. 审核后端权限中"管理员只能访问商家 API"的粒度和登录限速。
12. 核对许可证与收费插件边界：**MIT 核心许可不自动覆盖所有插件、图片和商用第三方素材**。

### 6.3 关键技术选型（已锁定，实现与之一致）

| 端 | 选型 |
|---|---|
| 顾客小程序 | uni-app（编译为微信小程序，**非 web-view 套壳**） |
| 商家 App | Kotlin + Jetpack Compose + Material 3（**非 WebView 套壳**） |
| 架构 | 单 Activity + Navigation Compose，feature 分包 |
| 状态 | ViewModel + StateFlow / Coroutines |
| 网络 | Retrofit + OkHttp + kotlinx.serialization |
| DI | Hilt（KSP） |
| 本地存储 | EncryptedSharedPreferences（凭据） |
| 后台任务 | cron + 数据库 outbox（**不当秒级消息通道**） |
| 兼容基线 | minSdk 24（覆盖商家在用旧机型），compileSdk / targetSdk 34 |
| 构建 | Gradle Kotlin DSL + version catalog，依赖全部锁版本 |

> 与早期规划的差异说明：
> - **minSdk 由 26 下调至 24** —— 商家端面向的店主机型普遍偏旧，Android 7.0 覆盖率显著更高。
> - **未引入 Room** —— 当前无离线读写需求；只读缓存留待有实际场景时再加，避免无谓复杂度。
> - **Repository 不再是 Mock** —— 已实现真实的 Retrofit 调用、envelope 解包与错误分类，仅后端持久化层仍为桩。

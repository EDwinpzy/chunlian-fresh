# 春连鲜选 · 设计规范 v1.0

> 风格方案：**01 有机鲜绿（Organic Fresh）**
> 适用范围：顾客端网页版（`apps/customer-web`）、顾客端安卓（`apps/customer-android`）、店主端安卓（`apps/merchant-android`）
> 状态：三端已落地同一套 Token，代码位置见 §9。

---

## 0. 这套设计要解决什么

社区生鲜的三个真实约束决定了视觉方向：

1. **同一家店要出现在三个端上。** 顾客在浏览器和 App 里看到的必须是同一个品牌色、同一套圆角、同一个价格红。任何一处走样，用户都会怀疑「这是不是同一家店」。
2. **店主是全天挂在后台的重度用户。** 界面要低饱和、不刺眼、数字要能一眼扫出异常。所以主色不做大面积铺底，只用在小面积行动点。
3. **顾客是「顺手买菜」的轻度用户。** 首页第一屏必须能完成「看到想吃的 → 加进购物车」，所以首屏信息密度优先于装饰。

结论：**低饱和的自然有机绿 + 奶油白底 + 小面积金色点缀**。安静、可信、不抢商品图的戏。

## 1. 设计原则

| # | 原则 | 落地要求 |
|---|---|---|
| 1 | **内容优先于容器** | 默认卡片只用 1px 浅边框分层，不用阴影；阴影只留给「需要浮起来」的元素（主推卡、悬浮操作条、弹窗） |
| 2 | **主色是行动色，不是背景色** | 深绿只用于主按钮、选中态、品牌标题。大面积铺底一律用奶油白 |
| 3 | **金额必须能纵向对齐** | 所有数字使用等宽字形（tabular figures），金额右对齐 |
| 4 | **状态不能只靠颜色** | 每个状态标签都必须带文字。色盲用户占男性约 8% |
| 5 | **实收与应收分列，绝不相加** | 视觉上必须分开呈现，用不同色相区分，不做「合计」数字 |
| 6 | **点击目标 ≥ 48dp** | 店主单手操作、顾客在颠簸的公交上点，都需要容错 |
| 7 | **弱网可感知** | 每个列表都有骨架屏、空态、错误重试三种视觉状态。**列表用骨架屏，详情/设置页用居中转圈**——列表的形状可预测，骨架能告诉用户「等的是什么」；详情页形状不可预测，骨架反而会误导 |
| 8 | **层级不超过 3 层** | 底部 Tab 顾客端 4 个、店主端 5 个封顶 |

## 2. 颜色

### 2.1 品牌绿（Brand）

深绿是整套系统的骨架色。600 是主色，700 是深色（主按钮、品牌标题）。

| Token | Hex | 用途 |
|---|---|---|
| `brand-50` | `#F2F7F4` | 极淡绿底，区块区分 |
| `brand-100` | `#E3EEE6` | 次级按钮底、选中行底、图标底座 |
| `brand-200` | `#C4DCD0` | 描边、进度槽 |
| `brand-300` | `#9CC4B2` | 禁用态主色 |
| `brand-400` | `#6BA48C` | 图表次级 |
| `brand-500` | `#43806A` | 悬停态 |
| **`brand-600`** | **`#245947`** | **主色**：互动边框、主要图标、次级按钮文字 |
| **`brand-700`** | **`#173F34`** | **深色**：主按钮底、品牌标题、营收卡底 |
| `brand-800` | `#0F2C24` | 深色底上的按下态 |
| `brand-900` | `#081B16` | 极深，仅用于深色浮层 |

> **为什么 700 比 600 更深还用于主按钮**：主按钮需要在奶油白底上有足够对比度（`#173F34` on `#F8F9F5` ≈ 11.2:1，远超 AAA）。600 在白底上只有约 7.8:1，做小字偏弱。

### 2.2 金色点缀（Gold）

金色**只做装饰**：特价徽标、分隔装饰、印章。**绝不做按钮文字主体色**——`#D7A766` 在白底上对比度约 2.1:1，做文字是不可读的。

| Token | Hex | 用途 |
|---|---|---|
| `gold-50` | `#FDF8EF` | 极淡金底 |
| `gold-100` | `#F8EEDB` | 徽标底 |
| `gold-200` | `#EFD9B0` | 描边 |
| `gold-300` | `#E3C48C` | 深绿底上的金色文字（对比度 6.4:1 ✅） |
| **`gold-400`** | **`#D7A766`** | **主金**：徽标底、装饰线 |
| `gold-500` | `#C08F4B` | 悬停 |
| `gold-600` | `#A46B22` | 金色作为文字时的最浅可用值（对比度 4.6:1） |
| `gold-700` | `#7A4E14` | 深金文字 |

> 深绿卡片上的金色文字要用 `gold-300`，不能用 `gold-400`。`#D7A766` on `#173F34` 对比度约 4.1:1，勉强但偏弱。

### 2.3 中性色（Neutral，微暖）

底色带一点黄绿倾向（`#F8F9F5`），不是纯灰。这能让白色卡片「浮」在底上而不显脏。

| Token | Hex | 用途 |
|---|---|---|
| `neutral-0` | `#FFFFFF` | 卡片、弹窗、输入框 |
| **`neutral-50`** | **`#F8F9F5`** | **全局背景 Canvas** |
| `neutral-100` | `#F1F3EE` | 内嵌区块底、骨架屏基色 |
| **`neutral-150`** | **`#E7EAE4`** | **1px 分隔线 / 卡片边框** |
| `neutral-200` | `#DCE0D9` | 输入框描边 |
| `neutral-300` | `#C3C9C2` | 禁用描边 |
| `neutral-400` | `#A2AAA4` | 占位符文字 |
| `neutral-500` | `#88938B` | TextMuted：最小说明文字 |
| `neutral-600` | `#66736B` | TextSecondary：辅助文字 |
| `neutral-700` | `#4A554E` | 次级正文 |
| `neutral-800` | `#313B35` | 深色正文 |
| **`neutral-900`** | **`#1E2823`** | **TextPrimary：正文主色** |

### 2.4 语义色

| Token | 前景 | 浅底 | 用途 |
|---|---|---|---|
| `success` | `#277653` | `#E9F4EC` | 已付款、已送达、已完成 |
| `warning` | `#A46B22` | `#FFF3E4` | 未收款、配送中、库存预警、退款处理中 |
| `danger` | `#B53B39` | `#FCEDEB` | 退款、取消、删除、错误 |
| `info` | `#245947` | `#EEF3F0` | 待配送、中性提示 |
| **`price`** | **`#B94C3F`** | — | **价格、差额增加** |

> **为什么 price 和 danger 分开**：`#B94C3F` 比 `#B53B39` 更暖、更偏橙，读起来是「标价」而不是「报错」。价格是每天要看几十次的高频信息，用错误红会持续制造轻微焦虑。这两个色相非常接近但语义完全不同，**不要合并**。

### 2.5 深色底上的文字与容器

深绿卡片（营收卡、主推卡、订单状态卡）上：

| Token | 值 | 用途 |
|---|---|---|
| `on-brand` | `#FFFFFF` | 主数字、标题 |
| `on-brand-muted` | `rgba(255,255,255,.65)` | 标签、辅助说明 |
| `on-brand-accent` | `#E3C48C`（gold-300） | 深绿底上的金色价格 |
| `on-brand-translucent` | `rgba(255,255,255,.18)` | 深绿底上的容器：状态胶囊、图标底座 |
| `on-brand-translucent-muted` | `rgba(255,255,255,.10)` | 弱化容器：未选中、打烊态 |

> **深绿底上的容器只能靠白色透明度分层。**
> 不要用 Material 的 `surfaceVariant`——那是「浅色表面」，放到深绿卡上会变成一块突兀的灰白。
> 也不要直接写 `Color.White.copy(alpha = ...)`：透明度散落在各处时，
> 想整体调一次「深绿底上的容器强度」就得全仓库找一遍。

## 3. 字体与排版

### 3.1 字体族

| 平台 | 字体栈 |
|---|---|
| 网页版 | `-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Noto Sans CJK SC', 'Helvetica Neue', 'Microsoft YaHei', sans-serif` |
| 安卓 | `FontFamily.Default`（系统字体，跟随厂商中文字体） |

不引入自定义字体。安卓厂商中文字体差异大，内置字体反而会在部分机型上渲染异常。

### 3.2 字号阶梯（375pt 基准）

| Token | 网页 | 安卓 | 行高 | 字重 | 用途 |
|---|---|---|---|---|---|
| `display` | 28px | 28sp | 34 | Bold | 今日实收大数字 |
| `title` | 24px | 24sp | 31 | Bold | 页面主标题 |
| `headline` | 20px | 20sp | 26 | Bold | 价格大号、卡片主数字 |
| `section` | 18px | 18sp | 24 | SemiBold | 区块标题 |
| `product` | 15px | 15sp | 21 | SemiBold | 商品名、按钮文字 |
| `body` | 14px | 14sp | 22 | Normal | 正文 |
| `caption` | 12px | 12sp | 18 | Normal | 辅助说明 |
| `mini` | 11px | 11sp | 15 | Normal | 状态标签、最小说明 |

**只用两个字重层级**：`Normal(400)` 与 `SemiBold(600)`。大数字和主标题可用 `Bold(700)`。不使用 Medium/Light——中文在低字重下笔画会糊。

### 3.3 数字排版

- **所有金额、数量、日期**必须使用等宽数字：CSS `font-variant-numeric: tabular-nums`；Compose `TextStyle(fontFeatureSettings = "tnum")`。
- 金额展示格式：`¥` + 整数部分 + `.` + 两位小数，例如 `¥3,860.00`。千分位只在 ≥ 10000 时加。
- **绝不用浮点累加金额**。存储与传输一律整数分（`*_fen`），只在渲染的最后一步转字符串。

## 4. 间距、圆角、阴影、动效

### 4.1 间距（8pt 栅格）

| Token | 值 | 用途 |
|---|---|---|
| `space-1` | 4 | 图标与文字间隙 |
| `space-2` | 8 | 行内元素间隙、标签内边距 |
| `space-3` | 12 | 卡片间距、表单行间距 |
| `space-4` | 16 | **卡片内边距、页面左右边距** |
| `space-5` | 20 | 按钮横向内边距 |
| `space-6` | 24 | 区块间距 |
| `space-8` | 32 | 大区块分隔 |
| `space-10` | 40 | 空态上下留白 |

> **8pt 栅格管的是「版面节奏」，不是每个像素。**
> 页面边距、卡片间距、区块间距、组件高度必须落在这套阶梯上——它们决定了页面的呼吸感。
> 但**组件内部的微调**（如标签内边距 6px、角标偏移 2px、描边占位 1px）允许用 2/6/10 这类半档值：
> 强行对齐到 4/8/12 反而会让小元素显得松垮。
> 判断标准：如果这个值改变会让**页面整体节奏**变化，它就该走 Token；如果只影响一个 18px 见方的角标内部，不必。

### 4.2 圆角

| Token | 值 | 用途 |
|---|---|---|
| `radius-xs` | 6 | 微标签、小徽标 |
| `radius-sm` | 10 | 提示条、图标底座、骨架块 |
| `radius-md` | 15 | **按钮** |
| `radius-lg` | 18 | **标准卡片** |
| `radius-xl` | 22 | **主推卡、大卡片、图片容器** |
| `radius-sheet` | 24 | 底部浮层、弹窗 |
| `radius-pill` | 999 | 状态标签、分类胶囊、头像 |

> 这套圆角偏大（15/18/22），是「有机」气质的主要来源之一。圆角小于 12 会让界面显得硬、像工具软件。

### 4.3 阴影（层级 Elevation）

**默认卡片不用阴影**，靠 1px `neutral-150` 边框分层。阴影是稀缺资源。

| Token | 值 | 用途 |
|---|---|---|
| `elevation-1` | `0 2px 8px rgba(23,63,52,.05)` | 可点击卡片（商品卡） |
| `elevation-2` | `0 4px 14px rgba(23,63,52,.07)` | 主推卡、悬浮的指标卡 |
| `elevation-3` | `0 6px 24px rgba(23,63,52,.07)` | 底部固定操作条、悬浮按钮 |
| `elevation-sheet` | `0 -8px 32px rgba(23,63,52,.12)` | 底部浮层 |

阴影颜色用深绿 `rgba(23,63,52,…)` 而不是纯黑——纯黑阴影在奶油白底上会显脏。

### 4.4 动效

| Token | 值 | 用途 |
|---|---|---|
| `motion-fast` | 150ms | 按钮按下、标签切换 |
| `motion-base` | 200ms | 页面过渡、浮层进出 |
| `motion-slow` | 300ms | 底部浮层升起 |
| `ease-standard` | `cubic-bezier(.2,.8,.3,1)` | 默认 |
| `ease-out` | `cubic-bezier(0,0,.2,1)` | 元素进入 |

**按压反馈按元素类型分开：**

| 元素 | 反馈 | 理由 |
|---|---|---|
| 按钮 | `scale(0.985)` + 不透明度 0.9，150ms，**不用涟漪** | 店主单手操作时，缩放比涟漪更「确定」——手指盖住了按钮，涟漪看不见 |
| 可点击卡片 | 系统涟漪（安卓）/ `scale(0.985)`（网页） | 卡片面积大，缩放会带动整屏跳动；涟漪是安卓用户的肌肉记忆 |
| 列表行 | 系统涟漪 | 同上 |

不做弹跳、不做旋转、不做位移入场。

## 5. 布局

| 项 | 规格 |
|---|---|
| 基准宽度 | 375pt（网页版最大内容宽 560px 居中） |
| 页面左右边距 | 16 |
| 顶部标题栏 | 48（含状态栏下方） |
| 底部 Tab | 56 + `env(safe-area-inset-bottom)` |
| 底部固定操作条 | 72 + safe area |
| 卡片间距 | 12 |
| 区块间距 | 24 |
| 商品双列网格 | 列间距 10，图 1:1 |
| 点击目标最小 | 48 × 48 |

### 5.1 顾客端底部导航（5 Tab）

`首页` · `分类` · `购物车` · `订单` · `我的`

- 未选中：`neutral-500`；选中：`brand-700`，且图标与文字同时加粗（不只靠颜色区分）
- 购物车有商品时，图标右上角显示数量红点
- 安卓端使用 Material 3 的 `NavigationBar`，高度由系统决定；网页版固定 56px + `env(safe-area-inset-bottom)`

> **为什么是 5 个而不是 4 个**：设计稿（方案 01）画的是 4 Tab（首页/分类/购物车/我的），
> 但实际实现把「订单」独立成一个 Tab。订单是生鲜高频入口（顾客要反复查配送状态），
> 藏在「我的」二级页里会显著增加查看成本。5 个 Tab 仍在规范上限内，因此**以实现为准**。

### 5.2 店主端底部导航（4 Tab）

`工作台` · `订单` · `商品` · `我的`

- 商家端核心操作（配送、收款核实）必须落在屏幕下 1/3 的拇指热区
- 未读通知与待办在「工作台」的快捷入口上显示红点，**不显示数字**——
  数字会让店主误以为有 N 笔退款在处理，实际是 N 笔待确认，语义不同
- 「统计」「资金流水」从工作台的快捷入口进入，不占 Tab 位：
  它们是低频的「查看」动作，而 Tab 位应该留给高频的「操作」动作

## 6. 图标

| 项 | 规格 |
|---|---|
| 画布 | 24 × 24 |
| 描边 | 1.7px，圆头圆角（`stroke-linecap: round`） |
| 风格 | 线性描边，非填充 |
| 尺寸 | 16（行内）/ 20（按钮内）/ 24（导航）/ 28（空态插图） |
| 颜色 | 继承 `currentColor`，不单独指定 |

**图标必须配文字。** 生鲜用户中相当比例是中老年人，纯图标导航的识别率很低。

## 7. 组件规格

### 7.1 按钮

| 变体 | 底 | 字 | 描边 | 高度 | 圆角 |
|---|---|---|---|---|---|
| `primary` | `brand-700` | `#FFF` | — | 48 | `radius-md` |
| `secondary` | `brand-100` | `brand-700` | — | 48 | `radius-md` |
| `ghost` | `surface` | `neutral-900` | 1px `neutral-150` | 48 | `radius-md` |
| `danger` | `surface` | `danger` | 1px `danger` | 48 | `radius-md` |
| `text` | 透明 | `brand-600` | — | auto | — |

状态：`disabled` → 不透明度 45%；`loading` → 白色 CircularProgress 20dp 替换文字；`pressed` → `scale(.985)`。

### 7.2 状态标签 StatusChip

- 高度自适应，内边距 `2px 8px`，圆角 `radius-pill`，字号 `mini`
- 语义映射见 §2.4
- **必须带文字**，不能只有色块

### 7.3 卡片

| 变体 | 规格 |
|---|---|
| `card`（标准） | `surface` 底 + 1px `neutral-150` 边框 + `radius-lg` + 16 内边距 |
| `card--flat` | 无边框，`radius-xl`，`elevation-1` |
| `card--featured`（主推） | `brand-700` 底 + `radius-xl` + 白字，高度 128（店主端营收卡）/ 126（顾客端主推卡） |
| `card--product`（商品卡） | `surface` 底 + `radius-lg` + `elevation-1` + 8 内边距，图片 `radius-md` 1:1 |

### 7.4 指标卡 MetricCard（店主端）

- 最小高度 92，内边距 16，圆角 `radius-lg`
- 标签 `caption` `neutral-600` → 数值 `headline`/`display` Bold → 提示 `mini`
- `highlight` 变体：`brand-700` 底，标签 `on-brand-muted`，数值白色
- `alert` 变体：数值用 `warning`

### 7.5 提示条 NoticeBar

`radius-sm`，内边距 `8px 12px`，字号 `caption`，行高 18。底色取语义色的浅底，文字取语义色前景。

### 7.6 空态 EmptyBox

上下留白 48，水平 24。标题 `product` SemiBold → 说明 `caption` `neutral-600` 居中 → 可选主按钮。

### 7.7 价格文本 PriceText

`price` 色 + Bold + 等宽数字。原价用 `neutral-500` + 删除线，字号降一级。`/份`、`/盒` 等单位为 `mini` 常规字重。

### 7.8 输入框

高度 48，`surface` 底，1px `neutral-200` 描边，`radius-md`。聚焦态描边换 `brand-600` 并加 1px（不改变布局，用 `outline` 或 `box-shadow`）。占位符 `neutral-400`。

### 7.9 骨架屏

| 项 | 规格 |
|---|---|
| 底色 | `neutral-100` |
| 圆角 | `radius-sm`（10）；图片位用 `radius-md`（15） |
| 动效 | 明暗呼吸 0.55 → 1.0，900ms 线性往复 |
| 形状 | **必须与真实内容一致**——商品卡骨架要长得像商品卡，否则加载完会跳版 |

**用呼吸而不是流光扫过**：流光需要渐变，低端安卓机上会掉帧。
生鲜顾客相当比例在弱网下打开，骨架屏是这一屏唯一能看见的东西，不能卡。

现成组件：

| 端 | 组件 |
|---|---|
| 顾客端安卓 | `SkeletonBox` / `GoodsGridSkeleton` / `ListSkeleton` |

## 8. 无障碍

| 项 | 要求 |
|---|---|
| 正文对比度 | ≥ 4.5:1（`neutral-900` on `neutral-50` = 13.6:1 ✅） |
| 大字对比度 | ≥ 3:1 |
| 状态传达 | 颜色 + 文字双通道 |
| 系统字号 | 支持放大到 200% 不破版 |
| 金额 | 等宽数字 + 右对齐 |
| 深色模式 | **暂不开启**。跟随系统切深色会得到一套未验证对比度的配色，「收款金额看不清」是真实事故。等深色 Token 定稿再开 |
| 动态品牌色 | **关闭**。店主换个壁纸，收款按钮不该从深绿变紫色 |

## 11. 与方案 01 设计稿的差异说明

设计稿（`docs/design/ui-proposals.html` 方案 01）与本文档有几处**刻意的差异**，以代码实现为准：

| 项 | 设计稿 | 本规范 | 原因 |
|---|---|---|---|
| 价格色 | `#B53B39` | `#B94C3F` | 设计稿误用了 danger 红。价格是高频信息，用更暖的橙红能降低焦虑感，且与 danger 语义分离 |
| Canvas 背景 | `#F7F8F4` | `#F8F9F5` | 差异 1/255，肉眼不可辨。沿用已上线的值，避免三端全量改动与既有验收证据失效 |
| 顾客端底部导航 | 4 Tab | **5 Tab**（多一个「订单」） | 订单是生鲜高频入口，藏在「我的」二级页会增加查看成本 |
| 店主端底部导航 | 5 Tab | **4 Tab** | 「统计」「资金流水」是低频查看动作，移到工作台快捷入口；Tab 位留给高频操作 |
| 主推卡徽标 | 「今日特价 · 限 50 份」 | 顾客端不放促销徽标 | 该卡承载的是**店铺公告**而非促销。硬套促销徽标会让顾客以为点进去有折扣——文案与视觉不一致比不好看更糟 |
| 商品卡加购钮 | 圆形 `+` 直接加购 | 顾客端安卓为「去选购」胶囊；网页版保留 `+`（多规格自动跳详情） | 本店商品多 SKU，必须先进详情选规格。安卓列表页直接加购会跳过规格选择，顾客拿到错的商品；网页版已实现「多规格跳详情」所以可以保留 `+` |

其余所有色值、圆角、间距、字号均与设计稿一致。

### 11.1 小尺寸图标按钮的命中区

规范 §5 要求点击目标 ≥ 48dp。但商品卡右下角的加购钮如果做成 48px 的实心圆，
会把整张卡压垮。做法是**保持视觉尺寸不变，用伪元素外扩命中区**：

```css
.goods-card__add { width: 30px; height: 30px; }
.goods-card__add::after { content: ''; position: absolute; inset: -8px; }  /* 命中区 46px */
```

# 春连鲜选 · 常见商品库清单

**用途**：店主端「上架新菜」时，从这份预设库搜索选中，自动填好名称 / 规格 / 单位 / 建议分类 / 别名，店主只需改价格和库存即可上架。

**状态**：已内置于商家端应用（`preset-goods.json`），允许后续在后台管理系统中编辑和修改。

---

## 1. 设计决定（三条，都影响你怎么改这份清单）

### 1.1 不放参考价

清单里**没有价格列**。价格由店主自己定，预设库预填价格有真实风险——店主没留意就按一个不合适的数字上架了，而价格是直接涉及收款的字段。清单只负责「名称 / 规格 / 单位 / 分类 / 别名」这些**客观信息**。

### 1.2 分类是「建议分类」，不是强制分类

预设库里的分类名（叶菜类、水产类…）不一定和店铺自己配的分类一致。应用里的处理是：

1. 选中预设 → 按**名称**去匹配店铺已有分类
2. 匹配到 → 直接填上
3. 匹配不到 → 分类留空并提示店主选一个（**不自动新建分类**，避免店主在不知情的情况下多出一堆分类）

所以清单里的分类名要尽量贴合常见叫法。如果你店铺的分类名和这里不一样，改这一列就行。

### 1.3 别名是为了搜索

店主可能搜「西红柿」也可能搜「番茄」，可能搜「土豆」也可能搜「马铃薯」。别名列让这些叫法都能命中同一条。你可以按当地叫法补充——**这一列最值得你改**，因为它直接决定店主搜不搜得到。

## 15. 需要你确认的点

1. **分类拆分是否合适**？我把蔬菜拆成了「叶菜类 / 瓜果类 / 根茎类 / 花菜豆荚类」四类。如果你店里习惯更粗（比如统一叫「蔬菜」）或更细，告诉我。
2. **要加当地特色品吗**？清单是按通用生鲜店配的，你那边常卖的本地货可以补进来。
3. **规格是否要按你们的实际包装改**？现在是按「约500g/份」这类通用写法，如果你店里固定按 300g 或 1斤装卖，改这一列。
4. **要加「进货单位」和「销售单位」两列吗**？现在只有一个「单位」。如果你们进货按箱、销售按份，需要拆成两列。
5. **96 条够不够**？可以再扩到 150 条左右，覆盖更全。

顾客端 · 订单详情重设计样板

风格方案 01 有机鲜绿 · 点击下方标签切换五种订单状态，观察状态卡、进度条与底部操作的变化

这次改了什么

  • 状态卡顶到页首：深绿订单状态卡（规范 §2.5）合并了页头，状态文字、付款胶囊、进度条放进同一张卡，替代原来「一行孤零零的状态字」。
  • 四步进度条：已下单 → 配送中 → 已送达 → 已完成，当前步金点高亮；已取消订单不显示进度，改在卡内展示下单与取消时间。
  • 卡片自带标题行：去掉游离的「商品清单 / 订单信息」小节标题，改用卡头图标 + 标题 + 右侧附加信息（如「共 N 件」），滚动更短、层级更清楚。
  • 金额区重排：实付 / 应付用 20px 大字强调；已实付、待收货款、退款处理中分行分色显示、绝不相加（原则 5）；行单价（如 ¥4.50/份）补在行右侧。
  • 期望送达独立成条：淡绿底时钟条放在地址下方，顾客最高频查看的信息不再混在普通键值行里。
  • 操作条按状态显隐：待付款 = 取消 + 修改；已送达 = 确认收货；已取消 = 重新下单（新增建议）；配送中与已完成不出操作条。
  • 扫码付款卡放最后：扫码预付 / 货到扫码不再插在状态卡和地址之间打断阅读，改为页面最后一张卡，紧贴底部操作条（2026-10-17 定稿）。
  • Token 零新增：色值、圆角 15/18、字号阶梯、等宽数字、强制浅色全部沿用 DESIGN-SYSTEM v1.0（仅补齐 §2.5 已定义、网页版此前未用到的 on-brand 半透明容器两个值）；确认方向后即可按此结构改 OrderDetailView.vue 与安卓端同名页面。

样板为纯静态演示，二维码为示意图形，未接后端。落地时结构对应 OrderDetailView.vue 的现有数据字段（order_status / payment_state / can_* 等），不需要新增接口。
